# ContentTranscoding

MP4 영상을 HEVC(H.265)로 인코딩하고, 원본과 비교한 PSNR·SSIM이 설정한 기준을 만족하면서 **영상 비트레이트와 전체 파일 크기가 모두 감소한 경우에만** 결과를 저장합니다. 원본 파일은 유지합니다.

## 실행 환경

- Python 3.10 이상. 별도의 Python 패키지는 필요하지 않습니다.
- `ffmpeg`, `ffprobe`가 PATH에 있어야 합니다. `libx265` 인코더가 포함된 FFmpeg를 사용하세요. FFmpeg 8.0.1에서 통합 테스트를 수행했습니다.
- NVIDIA 인코딩을 사용하려면 `hevc_nvenc`를 지원하는 FFmpeg, GPU, 드라이버가 필요합니다.

## 사용법

```powershell
python main.py --path "D:\videos"
python main.py --path "D:\videos" --encoder cpu
python main.py --path "D:\videos" --psnr 42 --ssim 0.95 --ratios 0.4 0.5 0.6 0.7 0.8 0.9
python main.py --threshold
```

`--encoder auto`가 기본값입니다. NVENC 인코딩이 실패하면 같은 비트레이트에서 CPU `libx265`로 재시도하며, 이후 파일도 CPU로 처리합니다. `--encoder cuda`는 CPU로 전환하지 않습니다. 디코딩은 CPU를 사용하므로 GPU의 디코딩 지원 형식에 의존하지 않습니다.

지정한 디렉터리 바로 아래의 `.mp4` 파일만 처리하며 확장자 대소문자는 구분하지 않습니다. 하위 디렉터리와 심볼릭 링크 파일은 처리하지 않습니다.

## 화질 판정과 재시도

1. 원본 영상 스트림의 비트레이트를 확인합니다. 값이 없으면 영상 패킷 크기와 재생 시간으로 계산합니다. 오디오를 포함한 컨테이너 비트레이트를 영상 비트레이트로 사용하지 않습니다.
2. 기본적으로 원본 영상 비트레이트의 60%, 70%, 80%, 90% 순서로 인코딩합니다. 매번 **원본**을 입력으로 사용합니다.
3. 원본과 결과의 해상도, 픽셀 형식/비트 깊이, 디코딩한 프레임 수, 재생 시간, 스트림 구성, 알려진 색상·회전 정보를 검사합니다. 오디오·자막·추가 영상 스트림은 재인코딩 없이 모두 복사합니다. 복사할 수 없는 스트림은 조용히 제외하지 않고 해당 파일을 실패 처리합니다.
4. 모든 프레임을 순서대로 비교합니다. PSNR 전체 평균과 Y 채널이 모두 **40 dB 이상**, SSIM 전체 평균과 Y 채널이 모두 **0.93 이상**이어야 합니다. 임계값은 옵션으로 변경할 수 있습니다.
5. 화질이 부족하면 다음 비트레이트로 재시도합니다. 화질을 통과한 결과의 실제 영상 비트레이트와 파일 크기가 모두 원본보다 작으면 채택합니다. 화질은 통과했지만 크기나 비트레이트가 줄지 않으면 원본을 유지합니다.

PSNR은 dB 수치의 단순 산술평균이 아니라, FFmpeg가 전체 프레임의 MSE를 누적해 계산한 최종 평균을 사용합니다. 따라서 일부 동일 프레임의 무한대 PSNR이 다른 프레임의 화질 저하를 가리지 않습니다. 판정 전에 수치를 추가로 반올림하지 않습니다. 계산 방식은 [FFmpeg PSNR 문서](https://ffmpeg.org/ffmpeg-filters.html#psnr)를 따릅니다.

현재 탐색은 지정한 후보 중 처음 조건을 만족하는 결과를 선택합니다. 가능한 모든 비트레이트에서 최솟값을 찾는 방식은 아닙니다. 더 강한 압축을 시도하려면 `--ratios`에 낮은 값을 추가하세요. 비율은 0과 1 사이의 중복 없는 오름차순이어야 합니다.

## 결과와 실패 처리

- 채택한 영상은 입력 디렉터리의 `done/`에 저장합니다. 같은 이름의 결과가 이미 있으면 덮어쓰지 않고 해당 파일을 실패로 기록합니다. 다시 처리하려면 기존 결과를 다른 곳으로 이동하거나 이름을 변경하세요.
- 실행 결과는 `done/measured_data.csv`와 `done/measured_data.json`에 기록합니다. 기존 보고서는 유지하고 새 보고서에는 `_1`, `_2` 등의 번호를 붙입니다.
- `status`는 `accepted`(채택), `unchanged`(조건을 만족하는 압축 결과가 없어 원본 유지), `failed`(인코딩·검사·저장 오류)입니다. 실패 사유, 시도 횟수, 목표/실제 비트레이트도 기록합니다.
- `ratio`는 후보 파일 크기 / 원본 파일 크기입니다. `unchanged`의 측정값은 마지막으로 검사를 마친 뒤 폐기한 후보의 값입니다. 측정하지 못한 값은 JSON에서 `null`, CSV에서 빈 칸입니다. 모든 프레임이 동일한 PSNR은 JSON에서 문자열 `"inf"`로 기록합니다.
- 정상 처리와 `unchanged`는 종료 코드 0, 처리·출력 오류는 1, 잘못된 인자는 2, 사용자 중단은 130입니다. 실패 파일이 있어도 나머지 파일 처리를 계속합니다.
- 실행마다 `temporary/run-*` 작업 폴더를 만들며, 이전 작업의 측정 파일을 재사용하지 않습니다. 결과 저장/이동에 실패하면 복구할 수 있도록 작업 파일과 측정 로그를 남깁니다. 중단된 작업도 해당 폴더에 남습니다.

10비트, 가변 프레임레이트, 디스플레이 회전은 유지 여부를 검사합니다. 정적 HDR 메타데이터는 첫 1초의 디코딩 프레임에서 확인하고 결과와 일치하지 않으면 채택하지 않습니다. Dolby Vision 및 검사 중 발견한 동적 HDR은 지원하지 않아 원본을 유지하고 실패로 기록합니다. 동적 HDR 콘텐츠에는 이 도구를 사용하지 마세요. PSNR·SSIM 기준은 전체 평균 기준으로, 장면별 최저 화질이나 사람의 체감 화질을 보장하지 않습니다.

## 웹 화면으로 실행

```powershell
python web_server.py --open
```

브라우저에서 [http://127.0.0.1:8765](http://127.0.0.1:8765)를 엽니다. Python 표준 라이브러리만 사용하므로 웹서버를 실행하는 데 Node.js나 별도의 Python 패키지가 필요하지 않습니다.

1. **파일 선택 / 폴더 선택**: 화면 안의 파일 탐색기로 웹서버가 실행 중인 컴퓨터의 영상을 선택합니다. 파일은 여러 폴더에서 여러 개 선택할 수 있습니다. 폴더는 하위 폴더 포함 여부를 설정할 수 있습니다. 업로드하지 않고 원본 경로에서 읽습니다.
2. **화질 설정**: 균형 프리셋(40 dB / 0.93), 높은 화질 프리셋(42 dB / 0.95), 직접 설정을 제공합니다. 인코더와 비트레이트 재시도 비율도 설정할 수 있습니다.
3. **트랜스코딩 시작**: 별도 프로세스에서 실행하므로 웹 화면이 멈추지 않습니다. 분석·인코딩·검증 단계, 재시도 횟수, 처리한 파일 수, 측정값과 로그를 확인할 수 있습니다. 동시에 하나의 작업을 실행합니다.
4. **결과 확인**: 영상별 채택/원본 유지/실패 여부, PSNR·SSIM 전체/Y 채널, 실제 비트레이트, 크기와 감소율을 표시합니다. 채택 영상과 전체 CSV·JSON 보고서를 다운로드할 수 있습니다. 실행 기록은 서버를 다시 시작해도 유지됩니다.

**실행 기록 삭제**: 실행 기록 메뉴에서 결과 화면으로 이동해 삭제할 기록을 선택하고 **선택 기록 삭제**를 누르세요. **완료 기록 전체 삭제**는 완료·실패·중단된 기록을 한 번에 지우며 실행 중인 작업은 보존합니다. 확인 창에서 삭제를 확정해야 적용됩니다. 원본과 결과 영상·보고서는 삭제하지 않습니다. 삭제한 기록은 재시작 후에도 다시 나타나지 않으며 웹에서 조회·다운로드할 수 없으므로, 필요한 파일은 미리 다운로드하거나 확인 창에 표시된 보관 폴더에서 찾으세요.

웹 작업의 결과는 `.web-data/jobs/<작업 ID>/outputs/<그룹 번호>/done/`에 저장합니다. 서로 다른 폴더에서 이름이 같은 파일을 선택해도 결과가 충돌하지 않습니다. 원본 폴더의 `done/`에는 웹 결과를 쓰지 않으며, 원본은 수정하지 않습니다. `.web-data/`에는 실행 기록·보고서·작업 로그도 저장하고 Git에서는 제외합니다.

폴더를 재귀적으로 선택할 때 `done`, `temporary`, 숨김 폴더, 링크는 제외합니다. 한 번에 최대 5,000개 영상을 선택할 수 있습니다. 선택 목록이 200개를 넘으면 화면에는 앞 200개만 표시하고 작업에서는 선택한 전체 파일을 처리합니다.

```powershell
# 다른 포트 사용
python web_server.py --port 9000

# 파일 탐색 범위를 지정한 폴더로 제한 (여러 번 지정 가능)
python web_server.py --root "D:\videos" --root "E:\archive"

# 실행 기록과 결과 저장 위치 변경
python web_server.py --data-dir "D:\transcoding-work"
```

기본 파일 탐색 범위는 Windows의 사용 가능한 드라이브이며, 다른 운영체제에서는 사용자 홈과 프로젝트 폴더입니다. 서버는 `127.0.0.1`에서만 연결을 받습니다. 다른 웹사이트의 요청과 허용되지 않은 호스트를 차단하고, 작업 시작 요청에는 페이지별 토큰을 확인합니다. 인터넷 공개용 서버가 아닌 로컬 작업 도구입니다.

브라우저를 닫아도 서버 프로세스가 켜져 있으면 작업은 계속됩니다. `Ctrl+C`로 서버를 종료하면 진행 중인 작업을 완료하고 기록을 저장할 때까지 기다립니다. 강제 종료된 작업은 다음 실행에서 `중단됨`으로 표시되므로 새 작업으로 다시 실행하세요. 같은 저장 폴더를 사용하는 서버의 중복 실행은 방지합니다.

화면 디자인은 [Linear의 2026 UI 개편](https://linear.app/now/behind-the-latest-design-refresh)과 [Vercel Geist](https://vercel.com/geist/introduction)의 정보 위계·색상 사용을 참고했습니다. 반응형 배치, 키보드 조작, 대화상자 포커스, 모션 감소 설정을 지원하며 외부 폰트나 CDN 연결 없이 동작합니다.

## 검증

```powershell
python -m unittest discover -s tests -v
```

FFmpeg가 있으면 테스트에서 짧은 영상을 직접 생성하여 인코딩, 전체 프레임 측정, 다중 오디오 복사, 10비트·가변 프레임레이트·회전, HDR 메타데이터 검사, 패킷 기반 비트레이트 계산을 검증합니다. FFmpeg가 없으면 통합 테스트만 건너뜁니다.

웹 서버 테스트는 파일·폴더 선택, 접근 범위, 요청 검증, 동시 작업 제한, 실행 기록 복원, 실제 트랜스코딩과 결과 다운로드, 원본 보존을 확인합니다.

기록 삭제 테스트는 개별·전체 삭제, 실행 중인 작업 제외, 결과 파일 보존, 재시작 후 삭제 유지 및 삭제 요청의 접근 권한을 검사합니다. 아래 화면 검사에서 삭제 동작도 확인하려면 별도 `--data-dir`로 테스트 서버를 띄우고 `FRAME_STUDIO_CHECK_DELETE=1` 환경 변수를 설정하세요. 삭제 화면 검사는 직접 생성한 샘플 작업의 기록만 삭제합니다.

선택적으로 Node.js 24 이상과 Chrome을 사용해 화면 동작도 검사할 수 있습니다. 웹 서버를 실행하고, 별도 프로필의 Chrome을 `--headless=new --remote-debugging-port=9222 --user-data-dir=<테스트 프로필 폴더>` 옵션으로 실행하여 웹 주소를 연 다음 `node tests/browser_smoke.mjs`를 실행하세요. 테스트는 샘플 영상을 생성해 파일·폴더 선택, 실행, 보고서 조회, 기록 복원, 모바일 배치를 확인하고 `.web-data/browser-artifacts/`에 화면을 저장합니다. Node.js는 이 선택적 화면 검사에만 필요합니다.
